# Protocol v4 reference

This is the wire format generated by Placebo, intended for runtime and contributor
work. For application development, start with the [typed editor quickstart](../README.md#build-your-first-app).
Use action bindings to generate forms and replies, and action route adapters to
register handlers. Handwritten protocol data bypasses those authoring checks.

Requests use form encoding and `Accept: application/vnd.placebo.update+json`.
Reads use GET; mutations use POST plus `X-Placebo-Request: 4`. The mutation
extractor requires that header and rejects cross-site browser metadata. A
rejected request gets a 403 HTML page a person can read: a native submission
sent before the runtime loaded says nothing was saved and how to retry, a stale
runtime version asks for a reload, and a cross-site submission is refused. This
assumes same-origin deployment without permissive CORS; applications still own
authentication and record-level authorization.

```json
{
  "version": 4,
  "action": "save-title",
  "target": "editor:42",
  "operation": "refresh-component",
  "html": "<article>Server-rendered component contents</article>",
  "outcome": "applied",
  "patches": [],
  "navigate": null
}
```

`replace-children` replaces a read region's contents. `refresh-component`
replaces component contents while retaining matching local units. Both keep
the target element.

A local unit is a typed control (`data-placebo-field`, keyed by its form's
action path and field name) or an explicit `data-placebo-local` subtree, which
takes precedence over the controls inside it. A unit keeps its node when any
control in it differs from its default (`defaultValue`, `defaultChecked`,
`defaultSelected`: the markup the server last rendered) or changed after the
request was sent. On an `applied` outcome, units with controls in the
submitting form also take the incoming markup unless they changed after
sending. Units without form controls are always kept. A kept unit's root takes
the incoming `aria-invalid`, `aria-describedby`, `aria-errormessage`,
`disabled`, `readonly`, and `required`. Live regions (`aria-live`, `status`,
`alert`, `log`, `output`) outside local units reuse the mounted node matched
by id or order. Focus inside a replaced subtree moves to the matching element
in the new markup; an `invalid` reply focuses the first `aria-invalid="true"`
control unless the person kept typing. Responses must match the initiating action, operation,
and captured target instance. Remounting the same id does not transfer ownership
of an old request to the new node.

Mutation bindings declare extra targets with `affects(target)`. Patches:

| Operation | Target | Fields |
|---|---|---|
| `replace-children` | versioned region | `revision`, `html`; skipped unless newer |
| `append-children` | plain region | `html` |
| `insert-item` | list | `item`, `position`, `html` (exactly the item element) |
| `move-item` | list | `item`, `position` |
| `remove-item` | list | `item` |
| `order-items` | list | `items`: listed items first, others after in current order |
| `refresh-component` | another component | `html`; skipped while it has a request in flight |
| `rerun-read` | read region | none; reruns every read form bound to it |

A position is `{"at": "start" | "end"}` or `{"at": "before" | "after", "item": id}`.
Items are direct children of the list with `data-placebo-item` and an id.
A missing item is skipped and an anchor that is gone places the item at the
end; the applied event reports them in `missingItems` and `misplacedItems`.
Replaced targets cannot overlap; a list may contain replaced targets, which
lets a form inside an item remove or move it.
`navigate` is a same-origin path, allowed only on an `applied` outcome, and the
browser goes there after applying the batch. The browser validates the batch
before touching the DOM. When a mutation response arrives but cannot be applied,
the component gets `data-placebo-stale` until its next applied reply.

Read forms may set `"history": true`: after a result applies, the page URL takes
the form's query (a new entry per query, with keystrokes in one text field
sharing one), and `popstate` restores the query into the form and reads again.

The Rust and browser halves must be upgraded together.

Mutation outcomes use HTTP 200 (`applied`), 422 (`invalid`), or 409 (`conflict`).
Validation/conflict HTML is applied intentionally. Other failures leave the
current UI intact and emit a diagnostic. Network failures are not automatically
retried; aborting a POST cannot undo a committed write.

The runtime emits `placebo:scheduled`, `request`, `applied`, `discarded`,
`deferred`, `ignored`, and `error` events (each prefixed with `placebo:`).
Details contain action/target names and outcome, reason, or error code where
applicable. `applied` also carries `refreshedLocal`, `preservedLocal` (each
with a `reason`), `skippedRegions`, `refreshedComponents`, `skippedComponents`,
`missingItems`, `misplacedItems`, `refetched`, `skippedReads`, and `navigate`. The example's interaction trace displays them.

Unexpected failures log actionable console errors by default. Enable execution
tracing from the browser console with `(await import('/placebo.js')).trace(true)`;
use `localStorage.setItem('placebo:trace', 'true')` before reloading to include
startup. Errors include request IDs and available method/path/status context,
plus whether a request started, an update applied, or a write's outcome is unknown.
Debug action routes log matching request IDs on the server. Unknown behaviors
are diagnosed; use `lazyBehavior()` for intentionally asynchronous registration.
See [diagnostics and the debugging evaluation](diagnostics.md).

HTML is trusted server output, not sanitizer input. Maud escapes text and
attribute values; applications own URL and executable-context safety. Inserted
script elements are inert; registered behaviors initialize declarative mounts.
The runtime is embedded in the Rust crate; in dev it
is served from its source file so JS edits reload without recompilation.
