# Protocol v3 reference

This is the wire format generated by Placebo, intended for runtime and contributor
work. For application development, start with the [typed editor quickstart](../README.md#build-your-first-app).
Use action bindings to generate forms and replies, and action route adapters to
register handlers. Handwritten protocol data bypasses those authoring checks.

Requests use form encoding and `Accept: application/vnd.placebo.update+json`.
Reads use GET; mutations use POST plus `X-Placebo-Request: 3`. The mutation
extractor requires that header and rejects cross-site browser metadata. This
assumes same-origin deployment without permissive CORS; applications still own
authentication and record-level authorization.

```json
{
  "version": 3,
  "action": "save-title",
  "target": "editor:42",
  "operation": "refresh-component",
  "html": "<article>Server-rendered component contents</article>",
  "outcome": "applied",
  "reset_local": [],
  "patches": []
}
```

`replace-children` replaces a read region's contents. `refresh-component`
replaces component contents while retaining matching local subtrees. Both keep
the target element. Responses must match the initiating action, operation,
and captured target instance. Remounting the same id does not transfer ownership
of an old request to the new node.

Mutation bindings declare extra regions with `affects(region)`. Replies may
include `also_replace(region, revision, html)` for versioned snapshots and
`also_append(region, html)` for unversioned collections. The browser validates
the batch before touching the DOM and skips stale shared snapshots. Version 3
also adds guarded `reset_local(key)` and the JavaScript `behavior(name, setup)`
lifecycle API. The Rust and browser halves must be upgraded together.

Mutation outcomes use HTTP 200 (`applied`), 422 (`invalid`), or 409 (`conflict`).
Validation/conflict HTML is applied intentionally. Other failures leave the
current UI intact and emit a diagnostic. Network failures are not automatically
retried; aborting a POST cannot undo a committed write.

The runtime emits `placebo:scheduled`, `request`, `applied`, `discarded`,
`deferred`, `ignored`, and `error` events (each prefixed with `placebo:`).
Details contain action/target names and outcome, reason, or error code where
applicable. The example's interaction trace displays them.

Unexpected failures log actionable console errors by default. Enable execution
tracing from the browser console with `(await import('/placebo.js')).trace(true)`;
use `localStorage.setItem('placebo:trace', 'true')` before reloading to include
startup. Errors include request IDs and available method/path/status context,
plus whether a request started, an update applied, or a write's outcome is unknown.
Debug action routes log matching request IDs on the server. Unknown behaviors
are diagnosed; use `lazyBehavior()` for intentionally asynchronous registration.
See [diagnostics and the debugging evaluation](diagnostics.md).

HTML is trusted server output, not sanitizer input. Maud escapes text and
attribute values; applications own URL and executable-context safety. Inserted
script elements are inert; registered behaviors initialize declarative mounts.
The runtime is embedded in the Rust crate; in dev it
is served from its source file so JS edits reload without recompilation.
